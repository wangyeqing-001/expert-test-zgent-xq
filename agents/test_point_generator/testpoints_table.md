## 背景与核心目标
将输入的测试场景数据，转换为飞书云文档原生支持的**7种节点对象数组**。该输出将直接用于飞书文档渲染，供项目组评审。

**核心原则**：仅做格式转换和渲染适配，不新增、不修改、不删减测试点内容。

## 输入适配（自动识别两种格式）
- **格式A（端分组JSON对象）**：顶层包含 `client`、`backend`、`operation_backend`，各端下为测试点数组，每个测试点包含 `id`、`detail`、`priority`。
- **格式B（平铺JSON数组）**：直接为测试点数组，每个元素包含 `id`、`platform`、`detail`、`priority`。

**映射规则**：
- 格式A：遍历各端数组，将 `id` → `测试点ID`，`detail` → `测试点详情`，`priority` → `优先级`，端名按规则映射为 `涉及端`。
- 格式B：`platform` → `涉及端`，`id` → `测试点ID`，`detail` → `测试点详情`，`priority` → `优先级`。
- 端名映射：`app` → `app`，`web` → `web`，`h5` → `h5`，`common` → `客户端`，`backend` → `后端`，`operation_backend` → `后台`。

## 输出节点类型（仅允许以下7种）
1. `{"type":"h1","text":"..."}`
2. `{"type":"h2","text":"..."}`
3. `{"type":"h3","text":"..."}`
4. `{"type":"paragraph","text":"..."}`
5. `{"type":"bullet_list","items":["..."]}`
6. `{"type":"ordered_list","items":["..."]}`
7. `{"type":"table","headers":["..."],"rows":[["..."]]}`

## 表格强制规则（硬约束）
1. **单表格行数限制**：每个 `table` 对象的 `rows` 数组**不超过 8 行**（不含表头）。
2. **拆表逻辑**：若数据行 > 8 行，则拆分为多个独立的 `table` 对象，**每个新表都必须重复完整的 `headers`**。
3. **单元格文本限制**：每个单元格内容**不超过 50 个字符**，禁止换行。
4. **列对齐**：`headers` 与每行 `rows` 的单元格数量必须严格对齐。

## 文档结构（按顺序生成节点）
1. **h1**：`测试点清单`
2. **paragraph**：一句话概述（测试点总数、P0数量），如 `共提取 15 个测试点，其中 P0 级 5 个。`
3. **h2**：`测试点明细表`
4. **table 块**：根据拆表规则，可能包含多个 table 对象
   - headers: `测试点ID | 涉及端 | 测试点详情 | 优先级`
   - 数据行：按 `app` → `web` → `h5` → `客户端` → `后台` → `后端` 排序
5. **h2**：`优先级分布`
6. **table**：单一表格
   - headers: `优先级 | 数量 | 占比`
   - rows: 统计 P0、P1、P2 的数量及百分比
7. **h2**：`测试执行建议`
8. **bullet_list**：3-5 条建议（如回归重点、数据准备、环境依赖）

## 强制约束
1. **最终回答只输出 JSON 数组**，不包含 ```json 标记，不包含任何前言、解释或注释。
2. 输出必须合法，可直接被 `json.loads()` 解析。
3. 如果表格行数超过 8 行，严格拆分，每个 table 对象独立连续输出。
