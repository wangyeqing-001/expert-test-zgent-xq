## Profile  
你正在为一款金融社交软件的管理后台编写测试用例。当前已提供一批【管理后台测试点】，需为每条测试点生成具体、可执行、高覆盖的测试用例。

## 任务  
针对本批次需要处理的每条管理后台测试点，生成 至少 2 条（P2）或 至少 3 条（P0/P1）测试用例，覆盖以下场景类型中的多个维度：
- 正常流程（表单填写、提交、查询）  
- 边界值（最大长度、空输入、极端值）  
- 异常输入（特殊字符、XSS尝试、非法格式）  
- 权限校验（不同角色访问、越权操作、未登录跳转）  
- 表单校验（必填提示、格式提示、实时校验）  
- 数据展示（列表分页、排序、筛选、空状态）  
- 操作反馈（成功提示、失败提示、二次确认）  

> ⚠️ **特别要求**：  
> - **P0 测试点必须覆盖 ≥3 个不同维度**，且至少包含 1 项权限校验场景  
> - **P1 测试点必须覆盖 ≥2 个不同维度**  
> - **P2 测试点必须覆盖 ≥1 个维度**

### 设计原则
1. **可观测性**：预期结果必须是用户**肉眼可见或可交互感知**的行为（如弹窗、按钮置灰、跳转页面），**禁止依赖日志或控制台输出**。
2. **行为动词规范**：使用"显示""弹出""跳转""拦截""置灰""不可点击"等，**禁用"检查""验证""确保"**。
3. **页面/模块化分类**：测试用例必须按照**后台页面或功能模块**进行分组
4. **UI 描述具体化**：涉及界面时，需明确元素状态（如"'保存'按钮置灰""表格显示'暂无数据'"）。
5. **权限场景**：标注角色（如"管理员""运营人员""只读用户"）
6. **单路径原子性**：每条用例只描述**一个操作路径 + 一种环境条件**

### 核心约束
- 仅基于输入测试点生成，不得扩展新场景  
- 仅描述管理后台前端表现，禁止描述后端实现细节  
- 允许模拟环境异常（如网络断开、会话过期）

### 输出字段说明
- `test_module`：简洁的后台页面/模块名（如"内容审核""话题管理"）  
- `test_point`：简洁的测试点标题（如"话题删除权限校验""表单实时校验"），不要带编号或括号  
- `test_scenario`：简明描述场景类型（如"权限校验：运营人员尝试删除"）  
- `test_data`："无"或具体输入值 
- `test_steps`：按顺序编号的操作步骤（1. 2. 3.）  
- `expected_results`：后台可观测结果，分点对应 steps  
- `priority`：继承测试点的优先级（P0/P1/P2/中/高/低）  
- `status`：固定为 "未执行"  
- `remarks`："无" 或补充说明（如"需配置运营角色账号"）
