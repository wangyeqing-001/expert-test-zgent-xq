# AI+搜索一期-需求文备份

## 1. 需求范围摘要  
本期聚焦搜索链路三端改造：在sug页新增「猜你想搜」模块并优化sug结果过滤逻辑；在搜索结果页全局删除「相关热门基金」卡片；在搜索中间页新增常驻「AI搜索」入口。处理实体为股票类query（type∈{11,82,90,30,0,61,6}）及ETF（type=13），核心动作是条件化展示、精准过滤与入口植入，最终产出为三端UI变更+后端推荐/过滤策略+灰度能力。

## 2. 输入/输出契约  
**输入条件**：  
- 必填字段：query文本、排序后首个sug的type值、该sug的状态（是否退市）、召回结果列表（含type、status、原始文本）  
- 可选字段：灰度开关标识（「猜你想搜」独立灰度开关、「sug逻辑优化」独立灰度开关）、可配类型白名单（股票/ETF type集合）、可配sug保留数量上限（当前默认3条）  
- 互斥/依赖关系：当首条sug为股票时，sug过滤逻辑生效；仅当召回结果为唯一标的（排除商业化结果后，仅剩同一公司多地上市主体）时，触发「猜你想搜」模块渲染  

**处理核心**：  
- 计算公式/规则：  
  - 唯一标的判定 = （过滤商业化结果后）剩余股票主体归属同一公司且仅存在A/港/美/ADR/-WR/-W等变体形式  
  - 「猜你想搜」内容生成 = 按优先级顺序取热股榜上榜理由→个股页「都在问」→（暂不启用）雪球思考主动提问→（暂不启用）实时股价异动，每条改写为≤15字、前N字为公司名称的短问题，经机审后取前3条通过项  
  - sug过滤 = 删除非【股票】+【ETF】类型结果、删除已退市股票、删除query自身匹配项  
- 状态扭转条件：无显式状态机，仅条件化展示/隐藏模块（如后端未返回「猜你想搜」数据则前端不渲染该模块）  
- 幂等/去重策略：未提及  

**输出结果**：  
- 成功返回结构：  
  - sug页响应中需区分「普通sug」与「猜你想搜」两类数据结构（字段未明确定义，但要求类型可区分）  
  - 搜索结果页响应中移除「相关热门基金」卡片（type=基金类卡片全量删除）  
  - 搜索中间页响应中新增「AI搜索」入口配置项（文案、显示开关）  
- 失败返回码/错误信息：未提及  

## 3. 数据一致性敏感点  
- 敏感点1：股票/ETF type枚举值定义 -> 文档现状：已提及（股票：11,82,90,30,0,61,6；ETF：13），推荐默认值：{11,82,90,30,0,61,6}∪{13}（置信度：高）  
- 敏感点2：唯一标的判定中「商业化结果」过滤范围 -> 文档现状：已提及（需过滤），但未定义商业化结果识别方式，推荐默认值：通过雪松后台「企业管理-已开通企业号」标识的企业账号关联内容（置信度：中）  
- 敏感点3：「猜你想搜」改写后字数上限与公司名前置强制要求 -> 文档现状：已提及（≤15字、前N字必须为公司名称），推荐默认值：严格校验首字符至第4字为公司全称或通用简称（如“腾讯”“阿里”），超长截断（置信度：高）  

## 4. 外部依赖与异常处理现状  
- 依赖项1：社区审核（机审）服务 -> 调用时机：「猜你想搜」内容生成后、返回前端前，文档现状：已提及，推荐默认值：调用统一机审接口，超时或失败时整条「猜你想搜」模块不展示（置信度：高）  
- 依赖项2：雪松后台企业号管理接口 -> 调用时机：判断用户是否为商业化客户时，文档现状：已提及（雪松后台-企业管理-已开通企业号），推荐默认值：HTTP GET /api/v1/enterprise/status?uid={uid}，返回is_enterprise=true视为商业化客户（置信度：中）  
- 依赖项3：实时股价异动数据源 -> 调用时机：「猜你想搜」优先级3数据来源，文档现状：已提及「本期先不做」，推荐默认值：该分支逻辑不启用，跳过（置信度：高）
